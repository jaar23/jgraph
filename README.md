# JGraph - Java Web Project Analyzer
## Enhanced with Source Code Capture

A powerful tool for analyzing Java web projects (Spring Boot, Jakarta EE) and visualizing their architecture through interactive graphs with **deep source code insights**.

## ✨ Features

### Core Analysis
- **Deep Code Analysis**: Parses Java source code using JavaParser
- **Annotation Detection**: Recognizes Spring (`@RestController`, `@Service`, `@Repository`) and Jakarta EE (`@Path`, `@Stateless`) annotations
- **Endpoint Extraction**: Captures REST endpoints with HTTP methods, paths, and parameters
- **Call Graph Generation**: Tracks method calls from endpoints → services → repositories
- **Dependency Mapping**: Identifies `@Autowired`/`@Inject` dependency injections

### 🆕 Enhanced Source Code Capture
- **Complexity Metrics**: Cyclomatic complexity, cognitive complexity, maintainability index
- **Natural Language Summaries**: Auto-generated human-readable descriptions (e.g., "Retrieves data. Authenticates user. Returns User or error")
- **Logic Flow Analysis**: Step-by-step operation tracking with categorization
- **Code Structure Extraction**: Conditionals, loops, method calls with nested representation
- **Variable Lifecycle Tracking**: Declaration, usage, read/write patterns (DETAILED mode)
- **Smart Compression**: Up to 76% file size reduction by removing trivial methods and deduplicating blocks

### Visualization
- **Interactive Graph**: Vue 3 frontend with vis-network for exploring architecture
- **Source Detail Panels**: View complexity metrics, logic flow, and code structure for any method
- **Visual Indicators**: 📄 icon and blue border on nodes with source code details
- **Smart Search**: Filter graph by keywords across functions, parameters, and flows
- **User Annotations**: Add notes and tags to any node

## 🚀 Quick Start

### Using the Enhanced run.sh Script (Recommended)

The project includes a convenient `run.sh` script that handles everything:

```bash
# Make it executable (first time only)
chmod +x run.sh

# Build the analyzer
./run.sh build

# Analyze a project (creates analysis.json + analysis-source-map.json)
./run.sh analyze /path/to/your/java/project

# Analyze with options
./run.sh analyze /path/to/project -o custom-output.json
./run.sh analyze /path/to/project --source-detail MINIMAL  # Smaller files
./run.sh analyze /path/to/project --source-detail DETAILED # With variables
./run.sh analyze /path/to/project --no-source              # Classic mode

# Test with sample project
./run.sh test

# Start the frontend viewer
./run.sh frontend

# See all options
./run.sh help
```

### Manual Setup

#### Option 1: Using Docker (No Java installation needed)

1. **Build the analyzer:**
```bash
cd analyzer
docker run --rm -v "$(pwd)":/app -w /app \
  maven:3.9-eclipse-temurin-17 mvn clean package -DskipTests
```

2. **Analyze a Java project:**
```bash
java -jar target/jgraph-analyzer-1.0.0.jar /path/to/project -o analysis.json
# This creates: analysis.json + analysis-source-map.json
```

#### Option 2: Using Local Java/Maven

1. **Build the analyzer:**
```bash
cd analyzer
mvn clean package -DskipTests
```

2. **Run the analyzer:**
```bash
java -jar target/jgraph-analyzer-1.0.0.jar /path/to/project -o output.json

# With source detail options:
java -jar target/jgraph-analyzer-1.0.0.jar /path/to/project \
  --source-detail STANDARD \  # MINIMAL | STANDARD | DETAILED
  -o output.json

# Without source capture (classic mode):
java -jar target/jgraph-analyzer-1.0.0.jar /path/to/project \
  --no-source \
  -o output.json
```

### Running the Frontend

1. **Install dependencies:**
```bash
cd frontend
npm install
```

2. **Start the dev server:**
```bash
npm run dev
```

3. **Open browser:**
Navigate to `http://localhost:5173`

4. **Upload the analysis.json** file generated by the analyzer
5. **Optionally upload the analysis-source-map.json** for enhanced source code insights

## 📄 Source Code Capture Features

### What's Included

The analyzer now generates **two files**:
1. **analysis.json** - Main architectural analysis (endpoints, services, repositories, call graph)
2. **analysis-source-map.json** - Detailed source code insights (NEW!)

### Detail Levels

Choose the level of detail based on your needs:

| Level | File Size | What's Included |
|-------|-----------|-----------------|
| **MINIMAL** | ~10-15 KB | Complexity metrics + operation counts only |
| **STANDARD** (default) | ~40-50 KB | + Code blocks + logic flow + summaries |
| **DETAILED** | ~80-100 KB | + Variable lifecycles + all usages |

### Source Map Contents

For each method, the source map provides:

#### 1. Complexity Metrics
- **Cyclomatic Complexity**: Number of decision points
- **Cognitive Complexity**: How hard it is to understand
- **Maintainability Index**: 0-100 score (higher is better)
- **Lines of Code**: Actual code lines
- **Nesting Depth**: Maximum nesting level
- **Statement Count**: Total statements

#### 2. Operations Summary
- Conditionals (if/switch)
- Loops (for/while/forEach)
- Method calls
- Exception handling (try/catch)
- Lambdas and streams
- Variable assignments

#### 3. Natural Language Summary
Auto-generated descriptions like:
- "Retrieves data. Authenticates user. Returns User."
- "Creates new entity. Validates permissions. Updates database. Returns HTTP response or error."
- "Processes stream. Transforms data. Returns list of entities."

#### 4. Logic Flow
Step-by-step operations categorized as:
- AUTHENTICATE / VALIDATE_AUTH
- QUERY_DATABASE / UPDATE_DATABASE
- CALL_EXTERNAL_SERVICE
- VALIDATE / CHECK_PERMISSION
- TRANSFORM_DATA / PROCESS_STREAM
- HANDLE_ERROR
- RETURN_RESPONSE / RETURN_RESULT

#### 5. Code Structure (STANDARD+)
Hierarchical representation of:
- Conditionals with then/else branches
- Loops with body
- Method calls with targets
- Returns with conditions
- Try-catch blocks

#### 6. Variable Lifecycles (DETAILED only)
For each variable:
- Declaration location
- All usage locations
- Read vs write operations
- Scope information

### Compression Benefits

The smart compression algorithm:
- Removes trivial getters/setters (LOC ≤ 3, complexity = 1)
- Deduplicates identical code blocks
- Normalizes whitespace

**Results**: Up to 76% file size reduction while preserving all important information!

### Frontend Integration

When you upload the source map file:
- **Visual Indicators**: 📄 icon on nodes with source details
- **Blue Border**: Methods with captured source
- **Summary Preview**: Truncated summary text on nodes
- **Detail Panel**: Full complexity metrics, logic flow, and code structure

## Architecture

### Backend Flow
1. **File Discovery**: Recursively find all `.java` files
2. **Parsing**: Use JavaParser to build AST
3. **First Pass**: Detect annotations, extract metadata
4. **Second Pass**: Analyze method calls, build relationships
5. **Graph Construction**: Create nodes and edges
6. **JSON Export**: Serialize to JSON with Jackson

### Frontend Flow
1. **File Upload**: User selects analysis JSON
2. **Data Loading**: Parse and validate JSON
3. **State Management**: Store in Pinia
4. **Graph Rendering**: vis-network creates visualization
5. **Search**: Filter data and update graph
6. **Details**: Display selected node information

## Limitations

- **Reflection**: Cannot analyze dynamic method calls via reflection
- **Lambdas**: Limited support for complex lambda expressions
- **AOP**: Aspect-oriented programming calls not tracked
- **External Libraries**: Only analyzes project code, not dependencies
- **Generated Code**: May not handle Lombok or other code generation tools perfectly

## Troubleshooting

### "Failed to parse file"
- Ensure Java files are syntactically correct
- Check for unsupported Java version syntax

### "No endpoints found"
- Verify annotations are correctly placed
- Check if project uses supported frameworks

### Graph not rendering
- Ensure JSON file is valid
- Check browser console for errors
- Try a smaller project first

### Memory issues with large projects
- Increase JVM memory: `java -Xmx4g -jar jgraph-analyzer.jar`
- Exclude test directories
- Process modules separately
